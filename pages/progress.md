## 다음에 할 일

1. 첫 번째 수직 흐름. 다섯 조각으로 나눔: 수주 → 계획(예약, 생산오더, 작업지시) → 실적(사이클과 불량에서 재집계, 마감하면 재고 입고) → 조립과 출하 → 끝에서 끝까지의 테스트. 조각마다 이슈와 PR 하나
   - 수주 조각에서 만들 것: `POST /api/sales-orders`, `GET /api/sales-orders/{수주번호}`, `GET /api/sales-orders`. 공통 예외와 오류 응답(`global`), springdoc(3.2.0. Maven Central에서 Spring Boot 4.1.2에 맞춰 나온 판임을 확인. 실제로 도는지는 붙일 때 확인), 준비 데이터(fixture)
   - 수주 조각의 규칙(2026-11-25에 정함): 수주번호는 core가 매김. 주문한 시각은 요청에 있으면 그것을, 없으면 `Clock`의 지금을 씀. 줄 하나라도 틀리면 전체를 받지 않음. 같은 고객의 같은 발주번호가 같은 내용으로 다시 오면 이미 있는 수주를 돌려주고, 내용이 다르면 거절함. 완제품만 주문할 수 있음
   - 수주 조각에서 하지 않는 것: 로그인과 권한(인증을 만들 때 붙임), 수주의 수정과 취소, 기준정보 API
   - 스키마에서 뺀 검사(수량이 0보다 큰지, 예약이 현재고를 넘지 않는지)는 프로그램이 봄. 작업지시의 시각이 작업일 안에 있는지(밤을 넘기지 않는지)와 원자재 이동에 LOT가 적혔는지도 DB가 막지 않으므로 프로그램이 검사하고 테스트로 확인
2. 과거 데이터의 시작일이 2026-01-01보다 앞이면 `cycle_log`의 첫 파티션 기준을 새 파일로 조정
3. KAMP 가이드북을 읽어 "가스"와 "초기허용불량" 라벨의 뜻 확인 (용어집의 "다시 확인할 것")
